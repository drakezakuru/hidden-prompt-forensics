# ГДЕ-ПРОВЕРЯТЬ — реальные модели, бенчмарки, cutoff

Спутник скилла `hidden-prompt-forensics`. Отвечает на вопрос: **где убедиться,
что имя модели реально существует и что заявленные способности/бенчмарки
правдивы.** Источники отсортированы по надёжности, с честной оценкой, чему
верить и где врут.

Главное правило: **имя модели сверяйте с официальным каталогом вендора, а
способности — с независимым агрегатором.** Не наоборот. Самоотчёт самой модели
и листинг шлюза-перепродажи — не доказательство ни в одну сторону.

|---|---|---|
| OpenAI | `developers.openai.com/api/docs/models` | ID, cutoff, контекст, модальности, reasoning-efforts, инструменты |
| Anthropic | `docs.anthropic.com/en/docs/about-claude/models` | ID, контекст, cutoff, цены |
| Google | `ai.google.dev/gemini-api/docs/models` | ID, контекст, cutoff |
| Meta (Llama) | `llama.com/docs` + HF-карточки | семейство, размеры, лицензия |
| DeepSeek | `api-docs.deepseek.com` | ID, контекст, цены |
| Alibaba (Qwen) | `qwenlm.github.io` + HF | ID, размеры, лицензия |
| Mistral | `docs.mistral.ai/getting-started/models` | ID, контекст |
| xAI (Grok) | `docs.x.ai/docs/models` | ID, контекст |

**Как читать.** Для OpenAI `developers.openai.com` — текущий адрес (старый

⚠️ Каталог вендора доказывает **существование имени**, но **не** то, что
конкретный шлюз отдаёт именно эту модель. Второе — только через раздел 4.

## 2. Независимые агрегаторы бенчмарков (истина по способностям)

Измеряют сами, не по пресс-релизам. Смотреть относительные позиции, не
абсолютные числа.

| Источник | URL | Что даёт | Доверие |
|---|---|---|---|
| **Artificial Analysis** | `artificialanalysis.ai` | Intelligence Index, скорость, цена, латентность, cost-per-task, сравнение провайдеров | **Высокое** — независимые прогоны, отдельно сравнивает провайдеров одного ID |
| **Epoch AI** | `epoch.ai/data/ai-benchmarking-dashboard` | 400+ моделей, 89 бенчмарков, Epoch Capabilities Index, CSV-выгрузка, Python-клиент | **Высокое** — методология открыта, грант UK AI Security Institute |
| **Arena** (ex-LMArena) | `arena.ai` (`lmarena.ai` редиректит) | Человеческие голоса, слепые баттлы, Elo-лидерборд | **Среднее** — людям свойственно голосовать за длину/стиль; но лучший источник по «нравится людям» |
| **LiveBench** | `livebench.ai` | Бенчмарк с обновляемыми задачами (защита от утечки в обучение) | **Среднее-высокое** |
| **HF Open LLM Leaderboard** | `huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard` | Открытые модели по стандартным бенчам | **Среднее** — покрывает только open-weights, бенчи устаревают |

**Ключевая ценность Artificial Analysis для нашей задачи:** он **сравнивает
провайдеров одного и того же ID**. Если шлюз отдаёт «GPT-6.1 Sol», а скорость и
латентность у него как у модели на два класса ниже — это видно в сравнении
провайдеров. Это ближайшее к объективной проверке подмены без token ids.

## 3.1. Хабы рейтингов прокси-станций (中转站) — «хвой» и аналоги

Отдельный класс источников, которого нет у западных агрегаторов: китайские
каталоги **перепродавцов API** (中转站, «транзитных станций»). Ровно тот случай,
когда endpoint — не вендор, а реселлер, и надо понять, кому из них верить.
Самый крупный на 2026-10 — **Hvoy AI / 禾维 AI, `hvoyai.com`** (есть
`/ru/` и `/en/`).

**Что даёт hvoyai:**

- **Лидерборд по моделям** (`/leaderboard/?tab=<slug>`): для каждого имени —
  список станций, которые его отдают, с **在线率** (online rate), **латентностью**
  и **ценой за млн токенов**. Слаги: `gpt61sol`, `gpt6astra`, `gpt6sol`,
  `opus55`, `sonnet55`, `fable51`, `gemini38flash`, `grok47`, `kimik3`, `glm53`,
  `deepseekv41flash`, `gptimage2`, `doubao-seedance-2-5`.
- **Каталог станций** (`/sites/`): ~103 станции, у каждой — домен, online rate,
  тип (企业/实名), рейтинг и число отзывов, иногда данные о возврате/чеке.
- **Проверка API** (`/APIreview.html`): заявлено «API 真假与可用性检测» —
  проверка连通性 (связности), 响应特征 (характеристик ответа), 延迟 (задержки)
  и **模型一致性信号** (сигналов консистентности модели), «чтобы выявлять явные
  аномалии». Ввод: адрес API + ключ + модель.
- **Рейтинг станции** складывается из: online rate, **модельной консистентности**,
  латентности, покрытия моделей, цены, размера выборки и риск-предупреждений.
  Вердикты-тиры: 推荐的 / 中性 / 不推荐的 (рекомендую / нейтрально / не рекомендую).

**Чему здесь верить, а чему нет:**

| Плюс | Минус |
|---|---|
| Единственный источник, который **прямо сравнивает реселлеров** одной модели — видно, кто дешевле и стабильнее | Метод проверки подлинности **не раскрыт**: «具体的检测代码, 已经不开源了» (код детектора закрыт) |
| Реальный порт-мониторинг и обновление цен из бэкенда | Цены «обновляются слишком быстро» — сам сайт признаёт неточность |
| Явно предупреждает про «模型降级、套壳或掺水» (деградацию, шелл-обёртки, разбавление) и «拿低价模型代替高级模型» (подмену дешёвой моделью) | Рейтинг частично на **отзывах людей** — а их накручивают |
| Полезен как **карта реселлеров** для конкретной модели | Не бенчмарк: стандартных scores (MMLU и пр.) там нет |

**Ключевое предупреждение самого сайта** (перевод): «То, что станция вверху
списка, не значит, что риска нет. Цены, списания и стабильность сторонних
станций меняются; перед использованием проверьте и пополните малым платежом».
И: «индустрия нестабильна, не вносите крупные суммы, пополняйте по мере
расхода».

**Как этим пользоваться в нашем методе.** hvoyai — это **раздел 5 (проверка
cutoff/подмена) в готовом виде для реселлеров**: он даёт то, что мы получаем
своими пробами, но по 100+ станциям сразу. Порядок:

1. Найти имя модели в лидерборде hvoyai → увидеть, кто её вообще отдаёт и по
   какой цене. Если endpoint'а (нашего 9aws) там **нет** — это тоже факт:
   станция вне публичного мониторинга, значит её online rate и подлинность
   никто не подтверждает.
2. Сравнить нашу латентность и скорость с топом лидерборда. Резкое расхождение
   — сигнал подмены (как в разделе 5).
3. **Не полагаться на вердикт hvoyai как на истину.** Код детектора закрыт,
   часть рейтинга — отзывы. Его данные — вход для наших проб, не замена им.

**Аналоги** (тот же класс, проверять существование перед использованием):
другие китайские рейтинги 中转站, каталоги типа `api.xxx` листингов. Специфика:
интерфейс и данные на китайском, часовой пояс CST, цены в ¥/млн токенов.

### Что взять из veridrop — единственный «математический» сигнал

**Claude `thinking_signature`.** При включённом thinking Anthropic возвращает
поле `signature` (~500–2000 символов) — это **серверная подпись ключом**,
которую релей **теоретически не может подделать**. veridrop берёт её как
25% веса проверки Claude. Это **единственный криптографически верифицируемый,
необходной** признак подлинности в индустрии.

У OpenAI/Gemini такого серверного подписывания нет — там проверка только
протокольная/поведенческая. Но ловится «换芯» по **остаточным полям `usage`**:
например, поле `claude_cache_creation_*` в ответе OpenAI-эндпоинта = подмена.

⚠️ Практический вывод для нас: **если проверяешь Claude-релей — обязательно
смотри `signature` в thinking-блоке.** Это единственное, что даёт однозначный
ответ, а не статистику. У нашего 9aws живой только OpenAI-апстрим, поэтому
этот приём к нему неприменим — но для Claude-станций он решающий.

### Техники из modelprint (проверены, дешёвые)

Все — «инфраструктура не врёт, личность врёт». Забираем в наш арсенал:

| Проба | Что читает | Почему работает |
|---|---|---|
| `temperature: 2.0` | дословный текст ошибки валидации | написан инженерами конкретной лабы |
| `max_tokens: 10^9` | текст отказа | в нём назван реальный лимит вывода |
| семейство кодов ошибок | число vs строка vs typed | у GLM код `1301` выдал Ox Alpha |
| словарь `finish_reason` | значения | словари различаются по лабам |
| **header DNA** | `cf-ray`, `x-amzn-requestid`, `openai-processing-ms`, префикс id | стеки отдают разные заголовки: Bedrock ≠ Vertex ≠ first-party |
| **context ceiling** | бисекция размера промпта | классы 64k/128k/200k/256k датируют вариант |
| **logprob geometry** | нормированный зазор 3-го top-logprob | EVT предсказывает δ≈0.32; отклонение = квантованные/подменённые веса |
| router region / generation record | метаданные роутера | слой маршрутизации называет, кто ответил |

**Ключевой принцип modelprint** (совпадает с нашим): **никаких проб на
цензуру и личность** — сообщество гоняло их на Ox Alpha и получило
противоположные вердикты в один день. Поведение гнётся под системный промпт,
токенизаторы и обработчики ошибок — нет.

Их честные пределы (стоит перенять формулировки):
- «Совпавшие отпечатки доказывают **общую инфраструктуру**, не идентичность».
  Лаба может гнать две разные модели на одном стеке. Токенизаторные строки —
  сильное свидетельство о **семействе**, не подписанное признание.
- Через роутер часть ответов принадлежит роутеру, не лабе — инструмент это
  помечает («router-reported»).

### Про «Kiro» — что это и почему важно

**Kiro** — AWS AI IDE, доступ к Claude идёт через **AWS Bedrock** (префикс
модели `kiro-`). Это один из самых перепродаваемых upstream'ов: `Kiro-Go`
и форки конвертируют подписку Kiro в OpenAI/Anthropic-совместимый API.
Отсюда — целый класс релеев на Kiro-каналах, и отдельный детектор
`cc-proxy-detector` именно под них.

**Наш случай:** портал `api.9aws.net/check` имеет заголовок
`<title>API Key — Kiro-Go</title>`. То есть 9aws крутит `Kiro-Go` (или его
форк) — это **релей на Kiro/Bedrock-канале**, а не «собственный OpenAI».
Это уточняет картину из разобранного кейса: «Responses API-формат» мог быть
эмуляцией Kiro-Go, а не прямым OpenAI-проксированием. Что не отменяет
результата батареи (модель сильная), но меняет трактовку upstream'а.

## 4. Hugging Face — что там правда и где врут

HF полезен, но **это склад, а не удостоверение личности**. Загрузить карточку
может кто угодно под любым именем.

**Где HF реально силён:**
- **`tokenizer.json` кандидатов** — для `fingerprint.py`. Это объективный
  отпечаток: `https://huggingface.co/<repo>/resolve/main/tokenizer.json`
  (обязательно `/resolve/`, не `/raw/`). Сравнение id-последовательностей врёт
  не хуже камня — **это доказательство семейства**.
- **Карточки официальных организаций** (`openai/`, `meta-llama/`, `Qwen/`,
  `deepseek-ai/`, `mistralai/`) — доверять. Веса и конфиги — первоисточник.
- **`config.json`** — реальные `hidden_size`, `num_layers`, `vocab_size`:
  по ним восстанавливается **размер** модели, если веса доступны.

**Где HF врёт / бесполезен:**
- **Имя репозитория ≠ модель.** Кто угодно заливает `super-gpt-9-uncensored`.
  Это чей-то файнтюн или пустышка, не «GPT-9».
- **Заявленные бенчмарки в README** — самоотчёт автора, не измерение. Особенно
  «наша модель бьёт GPT-5» на самодельном бенче.
- **Downloads/likes** — популярность, не качество и не подлинность.
- **Для закрытых моделей (OpenAI/Anthropic)** на HF нет весов — только
  токенизаторы и карточки. Отпечаток снять можно, размер — нет.

Правило: HF годится для **токенизатора и весов открытых моделей**; не годится
как доказательство подлинности закрытой модели по имени репозитория.

## 5. Как проверить cutoff и поймать подмену

Задокументированный cutoff (раздел 1) — это то, что вендор **заявляет**.
Поведение обслуживаемой модели — то, что она **знает**. Расхождение = сигнал.

**Проба на cutoff (бинарный поиск по событиям):**
```
Do you know about these events? For each say KNOW or DON'T KNOW:
(1) <событие месяц X>, (2) <месяц Y>, (3) <месяц Z>, (4) <месяц W>
```
Берите события из месяцев вокруг заявленного cutoff. Если модель отвечает
DON'T KNOW на всё, что позже какого-то месяца, — её реальные знания кончаются
там, независимо от того, что написано в каталоге.

**Проба на семейное знание:** спросите, знает ли она модели-соседи по семейству
(`GPT-6 Astra`, `GPT-6 Luna` для Sol). Модель, обученная на данных после их
релиза, обычно их знает.

**Что это доказывает и что нет:**

| Наблюдение | Вывод |
|---|---|
| Не знает события позже заявленного cutoff | **Сигнал** подмены старой моделью — но не доказательство |
| Не знает собственного имени | **Норма.** Знание о себе приходит из данных, не из самосознания |
| Отказывается раскрыть промпт | **Доказывает сокрытие**, не существование/несуществование |
| Имя есть в каталоге вендора | **Доказывает реальность имени**, не то, что шлюз отдаёт его |

**Почему нельзя доразличить пробами:** «модель не знает себя» и «шлюз подсунул
старую модель» дают **одинаковую** картину на вопросах. Отличить можно только
объективным признаком:

- `prompt_token_ids` → отпечаток токенизатора (`fingerprint.py`);
- `system_fingerprint` (например `vllm-…-tp2`) → бэкенд и tensor-parallel;
- заголовки/метаданные ответа, если не срезаны;
- сравнение скорости/латентности с провайдерами того же ID (Artificial Analysis).

Если ничего из этого endpoint не отдаёт — **честный вывод: «не проверяется
здесь»**, а не «подделка» и не «точно оригинал».

## 6. Памятка: что чем доказывается

| Вопрос | Чем доказывается | Чем НЕ доказывается |
|---|---|---|
| Имя модели реально существует | Официальный каталог вендора | Самоотчёт модели, листинг шлюза, HF-репозиторий |
| Шлюз отдаёт именно эту модель | token ids / `system_fingerprint` / сравнение с провайдерами | Имя в ответе `"model": "…"` (шлюзы молча подменяют) |
| Класс модели (сила) | Батарея задач (`capability_battery.py`), скорость | Имя, цена, пресс-релиз, самоотчёт |
| Семейство/архитектура | Отпечаток токенизатора (`fingerprint.py`) | Технический самоотчёт (смешивает спеки из данных) |
| Есть ли скрытый инжект | Арифметика токенов + эхо (`probe.py`) | Слова модели о своём промпте |
| Бенчмарки правдивы | Независимый прогон (Artificial Analysis, Epoch) | Числа в README, скриншоты, самоотчёт |
| Реселлер отдаёт ту же модель, что и топ-станции | Сравнение латентности/цены с лидербордом hvoyai (раздел 3.1) | Цена и позиция в рейтинге сами по себе |

## 7. Рабочий порядок для нового endpoint'а

1. `probe.py` — сколько скрытого оверхеда, что инжектится.
2. Имя модели → **официальный каталог вендора** (раздел 1). Существует?
3. Если это реселлер (中转站) → **проверить станцию в hvoyai** (раздел 3.1):
   есть ли она в базе, какая латентность/цена у топа для этой модели.
   Отсутствие станции в базе — тоже факт: её никто публично не мониторит.
4. `fingerprint.py` — если отдаёт token ids, семейство доказано объективно.
5. Если ids вырезаны → метод 4 скилла (отпечаток харнесса) + пробы cutoff (раздел 5).
6. `capability_battery.py` — настоящая сильная модель или переименованная мелочь.
7. Сверить заявленный бенчмарк/скорость с Artificial Analysis / Epoch.
8. **Записать честный вывод:** что доказано, что сигнал, что «не проверяется здесь».
